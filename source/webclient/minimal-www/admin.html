Server admin

Status and administration for this self-hosted install. Sections load when you open them. To change the shard or the secrets, edit the file named beside it and reload.

What this panel is

Read this once and you can ignore it. Every section below is either something the install resolved and you are checking, or something you can change from here.

Signed in as
Who the install thinks you are, and which admin ids it loaded. If it loaded none, this page would not have opened at all.
Shard this client connects to
What the client was built to connect to. Read-only: it comes from config.json, and the server address lives in .env, which a browser page has no business writing.
Client served at /
Whether a bare visit lands on ClassicUO or TazUO. Both stay reachable at their own URL either way. Changeable.
Developer console
Turns the client's console logging back on for everyone. Off by default because it is noisy and costs frames. Changeable.
Services
Whether Discord sign-in is configured, and whether the relay can see your UO server. This is the section to open first when something will not connect.
Game files
Which fileset the install resolved for your shard, and whether the hash map players verify their cached copy against has been built yet.
Disk usage
What the install is holding: game files, the database, player profiles. Walks the directories, so it is the one section that takes a moment.
Live sessions
Who is connected through the relay right now, and a way to disconnect one. Changeable. A kick drops the connection, nothing more — the player can reconnect immediately unless you also ban them.
Bans
Block a Discord id or an address from connecting. Changeable.
Scripting policy
Which verbs a player's scripts and macros may call, one tick-box each. Changeable.
Configuration backup
Downloads everything this panel can change, as one file. Not your .env or shard YAML.
Stored player data
Delete a player's saved settings and profile, or sweep guest accounts that have not returned. Changeable, and irreversible.

Nothing here edits .env, docker-compose.minimal.yml or your shard YAML. Those are files you own on the box, and a web form that wrote them would need a browser-reachable process holding write access to your filesystem — a much larger thing to leave running than a panel that reads.

Changes are stored in the database and take effect for the next player who loads the client; nobody already in the world is interrupted. The exceptions are a kick and a ban, which act at once.

Developer console

The client silences its own console for players. Turn this off while debugging and the boot log, the loader and the cache audit all print again — the same messages the ?dev=2 query parameter enables, but for everyone, without a URL.

checking…

Chunk snapshot cache

ClassicUO caches decoded map chunks in the browser, so walking back into an area it already knows skips reading the game files again. It is a large performance win — an A/B on the same build measured up to 30 more frames per second, and visibly fewer stutters — which is why the switch is here at all.

It is also the cause of an open defect. A chunk can be captured while part of its contents has already been freed; that partial copy is stored and reused, and the area comes back missing walls, floors or other static art until the cache is discarded. It is off by default for that reason. Turning it on trades correctness for speed — a fair trade on some installs, and yours to make. Players who hit it can load with ?snapshot=off once without waiting for you.

ClassicUO only. TazUO has no such cache, so this changes nothing on /tuo/. Either way it applies on each player’s next page load.

Game files

checking…

Brotli twins are a large bandwidth win, not a requirement: the loader asks for each file by name and brotli_static falls back to the raw file when no .br twin exists. (This note used to say every asset 404s without them, which was measured and found false — and it sent people building twins to fix a problem they did not have. Quality 11 takes hours over a full fileset; 9 takes a fraction for a few percent more.)

Live sessions

loading…

Relay sessions connected right now. Disconnecting drops the WebSocket; the player can simply reconnect, so this ends a stuck session rather than keeping anyone out — that is what a ban is for.

Bans

loading…

Enforced at the WebSocket upgrade, by Discord id and by IP — a ban here actually keeps somebody out. A Discord id is a 15-20 digit number; an IP entry takes CIDR notation (203.0.113.4/32 for one address). A reason is required. Leave days empty for permanent; anything longer than ten years is treated as permanent anyway.

⚠ IP bans catch whoever holds that address later, and on a home connection that can be a different person within a day. Prefer the Discord id where you have one.

Scripting policy

Every verb a player's scripts and macros can call, and what each one lets them do. Ticked = allowed. Untick one to switch it off for everyone on this install; the client is told the effective list at boot, so a change takes hold on the next load. Everything is allowed by default — this is a list of what you turn OFF, not what you turn on.

loading…

These gates sit on top of the client's own hard allow-list, which nothing here can widen — unticking makes scripting stricter, never looser. Blocking Allow LegionScript is the odd one out: it is a language gate, and turning it off leaves players with the JavaScript tab only. The console and waiting are always available, so an install with everything unticked still runs a script — it just cannot touch a character.

ready

Everything this panel can change: client default, dev console, scripting policy and bans. Deliberately not your shard YAML or .env — those are edited on the box and carry the host, port and secrets, which do not belong in a browser download.

Stored player data

loading…

You are the data controller for this install, so erasing is yours to do as well as the player's. Erase removes an account's settings, its identity row and its synced profile blobs; Drop profiles removes only the blobs, which is the narrower fix when a synced profile is corrupt but the account is fine.

⚠ Guests are not purged on a timer, deliberately. A guest id lives in that browser's local storage rather than in the cookie, so somebody can return months later still holding the same account — deleting by age would destroy data its owner could still reach, and the whole lot is tens of kilobytes.
